# 9. Aşama — Kullanıcı arayüzü

Piyasa raporunun P3 maddesi: *"9. aşama arayüz (yerel web) — eğitim satışı için
gerekli; ölçüt: uçtan uca demo"*. Komut satırı motoru çalıştırıyordu ama bir
öğretmenin, dinleyicinin ya da yatırımcının onu denemesi için terminal açması
gerekiyordu. Bu aşama **tek sayfalık yerel bir uygulama** ekler.

```bash
ophelia ui                      # http://127.0.0.1:8810/
ophelia ui --port 8811 --lan    # yerel ağa aç (aynı ağdaki başka bilgisayarlar)
```

## 1. Akış

```
komut (Türkçe)
   │  POST /compose  {command, seed, temperature, wav, xml}
   ▼
ophelia.nlp.compose  →  model (CPU)  →  MIDI
   │  arrange + render_parts
   ▼
salon + kompresör + −14 LUFS  →  WAV
   │  MusicXML (isteğe bağlı)
   ▼
JSON yanıt: tonalite · tempo · süre · nota · LUFS · dBTP · enstrümanlar · dosya yolları
   │
   ▼
sayfa: <audio> oynatıcı + WAV/MIDI/MusicXML indirme bağlantıları
```

Model **ilk istekte** yüklenir ve süreç boyunca bellekte kalır; ikinci üretim
belirgin biçimde hızlıdır. Aynı anda iki üretim makineyi boğmasın diye sunucuda
bir kilit var (istekler sıraya girer).

## 2. Uçlar

| Uç | İş |
| --- | --- |
| `GET /` | arayüz sayfası |
| `GET /api/status` | model hazır mı, hangi checkpoint |
| `POST /compose` | üretim; gövde en fazla 8 KB JSON |
| `GET /audio/<ad>` | WAV (`outputs/wav` ya da MIDI'nin yanı) |
| `GET /midi/<ad>` | MIDI (`outputs/midi`) |
| `GET /score/<ad>` | MusicXML (`outputs/scores` ya da MIDI'nin yanı) |

Dosya uçları **beyaz liste** ile çalışır: yalnız çıktı klasörlerinde gerçekten
var olan dosya adları servis edilir, `../` denemeleri 404 döner (testli).

## 3. Girdi doğrulama

Arayüz hatayı modele ulaşmadan yakalar (hepsi testli, 400 döner):

| Kural | Gerekçe |
| --- | --- |
| komut boş olamaz, ≤400 karakter | model bağlamını anlamsız istekle doldurmamak |
| tohum tam sayı, ≥0 ya da boş | rastgele üretimde `auto` |
| sıcaklık 0,1–2,0 | dışındaki değerler dinlenemez çıktı üretiyor |
| gövde ≤8 KB | bozuk/kötü niyetli istekte belleği korumak |

## 4. Ölçülen davranış

Bu makinede (i3-1315U, CPU):

| İstek | Süre | Çıktı |
| --- | --- | --- |
| "hüzünlü la minör, yavaş, 20 sn, yaylılar" (ilk istek, model yüklemesi dahil) | 11,6 sn | 111 nota · 20,0 sn · −14,0 LUFS · −4,2 dBTP |
| aynı istek (model bellekte) | 8,0 sn | aynı dosya adı (tohum sabit) |
| "la minör, 10 sn, yaylılar" | ~2 sn | 46 nota · −14,0 LUFS · −4,8 dBTP |

WAV dosyası istenen süreden uzundur (10 sn istek → 13 sn dosya): sona salon
kuyruğu eklenir. MIDI tam süreyi korur.

## 5. Güvenlik ve sınırlar

- Varsayılan **yalnız 127.0.0.1**. `--lan` bilinçli bir tercih: sayfada kimlik
  doğrulama yoktur, aynı ağdaki herkes üretim başlatabilir.
- Üretim CPU'da ve tek sırada; 4-5 kişi aynı anda kullanırsa istekler bekler.
- Geçmiş/oturum yok: sayfa yenilenince sonuç kaybolur (dosyalar diskte kalır).
- Nota düzenleme, enstrüman değiştirme, tempo değiştirme arayüzde **yok**; bunlar
  hâlâ komut metninden (`"melodi, armoni ve bas"`, `"çello ve keman"`) yönetiliyor.
- Bu arayüz bir ürün değil, bir demodur: hesap, kayıt, faturalama yok.

## 6. Kör dinleme testiyle ilişkisi

Arayüz ile A/B testi ayrı sunuculardır ve bu bilinçli:

| Araç | Kime | Ne için |
| --- | --- | --- |
| `ophelia ui` | geliştirici/öğretmen | komut → beste → dinle/indir |
| `ophelia abtest serve --lan` | dinleyiciler | kör karşılaştırma, oy toplama |

Dinleme testinde arayüz kullanılmaz: dinleyici komut yazmaz, yalnız iki kaydı
dinleyip oy verir. Arayüz ise "motorun ne yaptığını gösteren" vitrindir.
